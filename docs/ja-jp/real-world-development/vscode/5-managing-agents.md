GitHub Copilot を agent mode で使うと、コードベースの調査、変更の提案、ファイル編集、コマンド実行を自律的に行います。VS Code の Copilot Chat は、開発者のマシンでリアルタイムに実行される作業について、ツール呼び出しやファイル編集を確認できる画面を提供します。差分をインラインでレビューし、個々の変更を承認または取り消し、エディターを離れずに追加のプロンプトを送って会話を進められます。

この演習では、次の作業を行います。

- アクセシビリティ エージェントの作業をリアルタイムに監視する。
- 提案されたファイル編集をレビューして承認する。
- セッションの途中でエージェントに指示し、ハイ コントラストに加えてライト モードの切り替えを追加する。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントは、ハイ コントラスト モードを実装しています。作業中にデザイン チームから追加の要望があり、既定のテーマが暗すぎると感じるユーザー向けにライト モードの切り替えも追加してほしいとのことです。新たに会話を始めるのではなく、既存のセッションに指示を追加して作業を広げます。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調査したファイル、実行したコマンド、提案した編集を確認できます。ファイル編集は差分とともにチャット内に表示され、**Keep** と **Undo** を選択できます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールしてツール呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナル コマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がチャット内に表示されます。
   - **Keep** を選択すると変更を承認します。
   - **Undo** を選択すると変更を取り消し、エージェントに再度作業させます。
4. チャット上部の **Files changed** を開くと、このセッションでエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナル コマンドの実行などでツール呼び出しに許可が必要な場合、エージェントは一時停止して **Allow** を表示します。実行してもよいコマンドだけを許可してください。

5. エージェントがハイ コントラスト モードを実装し終えるまで待ちます。最後に変更内容の要約が表示されます。

## エージェントに指示してライト モードを追加する

ハイ コントラスト モードが完成したので、同じ会話でライト モードの切り替えも追加します。ユーザー インターフェイス (UI) の同じ領域に切り替えを追加するよう依頼します。同じチャット セッションを続けるため、エージェントはこれまでの作業、変更したコンポーネント、スタイルの方法、ローカル ストレージの使い方を引き継ぎます。

1. Copilot Chat の入力欄に次の追加プロンプトを送ります。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントがこれまでの変更を確認し、ライト モードの追加を提案する様子を確認します。
3. ハイ コントラスト モードのときと同じように、新しい編集を確認します。各差分で **Keep** または **Undo** を選択します。
4. エージェントが望まない方向に進んだ場合 (たとえば、好みに合わない方法でトグル UI をリファクタリングする場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、明確な追加メッセージを送ります。

> [!TIP]
> 作業中のセッションに指示を追加すると、最初からやり直すよりも速く調整できます。追加プロンプトを使って変更を依頼します (「カスケーディング スタイル シート (CSS) を簡潔にして、セレクターの重複ではなく CSS 変数を使う」など)、方向を修正します (「トグルを 3 つにせず、既存の設定パネルにライト モードを追加する」など)、または範囲を広げます (「2 つのトグルにキーボード ショートカットも追加する」など)。

## 変更されたファイルをレビューする

コミットする前に、エージェントが変更したファイル全体を簡単に確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティック ハイパーテキスト マークアップ言語 (HTML)、ローカル ストレージへの保存など、カスタム エージェントのアクセシビリティ パターンが反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode で、進行中のセッションを監視して調整しました。ファイルの編集を確認して承認または取り消し、コンテキストを失わずに追加のプロンプトで作業を広げました。

このレッスンでは、次の作業を行いました。

- エージェントの作業をリアルタイムに監視した。
- 個々のファイル編集を承認または取り消した。
- セッションの途中で追加のプロンプトを送り、エージェントに指示した。

次のレッスンでは、[アクセシビリティ機能をプル リクエストとして公開][next-lesson]し、ラボ中にローカルのカスタム エージェントが作成した変更をレビューします。
